# Changelog

Changes to protocols, benchmark definitions and results. Protocol versions are bumped whenever a
rule that changes F1 changes (see `src/spindlebench/protocols/`).

## Unreleased

### Data
- `spindlebench download cinc2018`: a subset of the PhysioNet/CinC 2018 training set (people aged
  18-64, fixed random order with seed 2018, first `--n`, default 250; list in `records_used.csv`).
- `spindlebench cache --only hmc,cinc2018` appends HMC (four EEG channels, 256 Hz) and CinC 2018 (six
  EEG channels, 200 Hz, read with `wfdb`) to the cache, staging only; a full `spindlebench cache`
  keeps their rows. New dependency: `wfdb`.
- CLI: a leading `--option` after `cache` or `download <db>` (e.g. `cache --boas-only`) is passed on;
  argparse's `REMAINDER` rejected it before.
- No protocol changed; no benchmark result changes.
- `spindlebench artefacts` (`spindlebench.data.artefacts`, version `artefacts.v1`): one shared artefact
  mask per recording, `cache/labels/<dataset>/<rec>__artefact.csv` (YASA `art_detect`, `method="std"`,
  5-s windows, |z| > 3 within each stage, wake included; 0.3 Hz high-pass first). Summary in
  `results/artefacts/`. Rejection only; nothing reads the mask yet, so no benchmark result changes.
- `detectors/common.py --clean`: an adapter runs on the artefact-free windows joined end to end;
  events are mapped back to recording time, events within 1 s of a join are dropped. Output
  `results/detections_clean/` (all four rule teachers on HMC, CinC 2018, DREAMS, NAP). The benchmark
  store `results/detections/` is unchanged.
- Student study, step 1 (`experiments/student/`, own uv project): splits, SUMOv2 preprocessing of the
  training nights, teacher masks and corpus agreement, label models (majority vote, soft, Dawid-Skene
  via crowd-kit with its early stop disabled, FlyingSquid), and consensus detections on the gold sets
  (`results/student/detections/`, scored in `results/student/consensus/`). No protocol changed.
- Student study, step 2: the student network (`experiments/student/model.py`; trunk S is SUMOv2's U-Net,
  state-dict compatible and output-identical, trained from scratch), losses, decoders D0/D1/D2, label-free
  validation (`validate.py`), training (`train.py`), injected validation nights and the identifiability
  check (`build_val_injection.py`, `score_val_injection.py`, `results/student/injection/`), and the
  `student_soft` pilot. Docs: `ARCHITECTURE.md`, `docs/student_architecture.md`, `docs/visual_guide.html`
  (generated by `experiments/student/visual_guide.py`). No protocol changed; no benchmark result changes.
- Student study, step 3 tooling: the restartable CPU-track grid (`run_all.py`), label-free selection and
  the freeze (`selection.py`), the gold-set run (`infer.py`) and a live dashboard (`dashboard/`).
- Student training runs live outside the repository, in `../runs/student/` (`SPINDLEBENCH_RUNS`);
  `train.py` and `run_all.py` take `--device cpu|cuda` (uv group `cpu`: torch 2.15.0; `cuda`: torch
  2.14.1+cu126 for a CUDA 12 driver). `run_gpu_grid.cmd` runs the GPU track unattended.
  The 2026-11-05 launcher stop left 10 runs incomplete; they are archived and rerun from scratch.
- Student GPU track (2026-11-06, RTX 4070): `run_gpu_grid.cmd` defaults to 4 workers (about 4.5 GB RAM
  per run; the GPU is compute-bound from 3 runs on, 4 runs give the same total batches per second).
  The dashboard shows either track (sidebar switch; GPU runs `*_gpu_s<seed>`, seeds 0–4, 30-pass
  budget) and GPU load; `lam1.5` renamed `lam0.1` to match `run_all.py`. `keep_awake.ps1` holds off
  system sleep while a training runs. No training code changed.
- `run_all.py --first a,b,...` (and `run_gpu_grid.cmd <workers> "a,b"`) moves matching jobs to the front
  of the queue. Used on 2026-11-06 21:15 to run `rules4_lam0`, `student_mv` and `student_ds` next, after
  the first GPU `student_rules4` runs lost diagonal dominance after warm-up (N2 6–10 per min) and
  `student_soft` under-detected. Order only; no job or setting changed.
- rules4-fix pilot (branch `rules4-fix`; nothing in the grid changed). In the GPU grid every
  `student_rules4` seed lost diagonal dominance after warm-up: the per-sample noise tables put the
  teachers' recall at 0.24–0.35 and the student over-detected (5–7.5 N2 spindles per min against about 2.6
  for the majority vote); `lam 0` halved it, no more. New options, off by default: `train.py --anchor ds
  [--anchor-delta D]` starts each teacher's table at its Dawid-Skene matrix and bounds the per-sample
  correction to +-D logits (D = 0 fixes it); `--init-from <run>` warm-starts the trunk from a finished run;
  `--stop-pass N` ends after pass N of the full schedule. `run_all.py --pilot` / `run_pilot.cmd`: variants
  fixA (anchor, D 0.5), fixB (D 0), fixC (fixA + trunk from `student_ds`), all `lam 0`, seeds 0 and 1,
  passes 1–5, judged on label-free signals only (dominance, N2 rate, agreement F1), no gold sets.
  Pilot result (2026-11-08): all six runs kept dominance through pass 5 (F1 vs majority vote 0.74–0.76,
  N2 2.4–3.5 per min; the grid's `global` ablation also held, at about 0.77 recall). fixC's warm start
  added nothing. `run_all.py --fix` / `run_fix.cmd [workers] wait`: fixA as full runs (seeds 0–4, full
  schedule) into `../runs/student_fix`, started when the main grid has finished training, then scored
  for selection.
- `selection.py score --device auto|cpu|cuda` (default auto: the GPU when torch sees one): the network
  runs on the GPU, deterministic as in training; decoding and matching stay on the CPU. Each run also
  writes `scores/<run>__meta.json` (device, torch, pass, checkpoint sha256, seconds). On the CPU the
  network took about 4 h per run (200 nights on one thread). A GPU and a CPU quick score of
  `student_rules4_global_gpu_s1` differ by at most 1 detection in about 970, F1 by at most 0.0004.
  On 2026-11-09 the CPU scoring of the GPU grid was stopped after 7 runs (moved to
  `selection/scores_cpu_archive/`) and all 60 runs were rescored on the GPU (`run_score.cmd student 6`).
- Faster decoders, same output: D2's forward recursion runs one boundary at a time in a numba-compiled
  loop (the block form stays as the fallback); D1 looks up the box pairing once and takes each box's and
  gap's max / min with one `reduceat`; the box score (mean p) for float64 input is a compiled copy of
  numpy's pairwise summation. Checked against the previous code on 12 injected nights of 4 runs: D0
  (144 cases), D1 (216 settings, with and without the confidence filter) and D2 (12 nights) are
  bit-identical, and so are 3000 slice means (lengths up to 900 000 samples). D1 3.5x, D2 50x faster.
  `numba` was already installed as a dependency of another package.
- Student study, amendment 10 (2026-11-09, before the freeze and any gold-set run;
  `experiments/student/README.md`): `selection.py freeze` freezes every run at D0, τ 0.5, no snapping,
  instead of the injection criterion's choice (τ 0.15 for every run, favouring over-detection; kept as
  `injection_choice`); the headline is `student_rules4` fixA; amendment 9's λ rule is retired and its
  table reported; a λ family with no surviving run is reported as failed. `summary_<track>.csv` for
  tracks other than cpu.
- `infer.py --track cpu|gpu --device auto|cpu|cuda`: `--track gpu` runs the freeze in `frozen_gpu.json`
  (refused if the file names another track); the network runs on the GPU when one is visible.
- Raw datasets: `paths.DATA` defaults to `datasets/` when that folder exists, else the repository folder
  as before. No path in the cache or the results changes.

## 0.1.0 (2026-10-30)

First public release.

### Detectors
- Luna `SPINDLES` (`detectors/luna`, id `luna_spindles`, program defaults) and S5
  (`detectors/s5`, ids `s5` and `s5_ens`, MODA weights) added, run on DREAMS and NAP and scored.
  No protocol changed; every earlier summary row is unchanged.

### Restructure (branch `restructure`)
- Core code moved into the `spindlebench` package (`src/spindlebench/`): event matching
  (`metrics.events`), point-mark scoring (`protocols.nap_points`, version `nap_points.v1`), NAP loaders
  (`data.nap`, `data.nap_annotations`), paths (`paths`). Every re-run result is byte-identical to the
  2026-10-28 snapshot.
- Detectors (phase 2): `detectors/<name>/manifest.json` for all 8 adapters (ids, method, upstream
  source and licence, adapter licence, weights, environment, lock, command); `spindlebench.detections`
  holds the detection file contract; `tests/test_detectors.py` checks manifests, id ownership and every
  stored detection file. `detectors/wonambi/uv.lock` added (matches the environment that produced the
  results). Detection runs and experiments now write provenance records (`spindlebench.provenance`,
  `detectors/common.py`). A re-run of `moelle` on DREAMS is byte-identical to the stored detections.
- DREAMS assessment rewritten (`protocols.dreams_assessment`, `dreams_assessment.v1`) from the published
  description of Devuyst et al. (2011) and our notes on its behaviour, replacing the literal port of the
  DREAMS MATLAB code (distributed under CC BY-NC-ND 3.0). Confirmation (`tests/test_dreams_assessment.py`):
  identical to the original MATLAB counts for the shipped automatic detections in all five comparisons
  and to the published 70.20% / 26.44%; identical to the old port on 107 of 140 detector rows, the rest
  within 4 events (F1 within 0.003). Causes, found by running the old port as a black box: it counts a
  detection starting at 0 s twice (A7, SSSM), and it handles clusters linked only through a third scorer
  in a way the description does not define.
- NAP detection outputs may be published (decision 2026-10-28; NAP is BSD 3-Clause on OSF).
- Release hygiene (phase 4): `CITATION.cff` (validated); REUSE 3.3 compliant licensing
  (`LICENSES/`, `REUSE.toml`; code MIT, docs and results CC BY 4.0, two GPL-3.0 ports with SPDX
  headers); pre-commit hooks (large files, merge conflicts, TOML/YAML/JSON, private keys, whitespace,
  ruff); CI on Linux and Windows (lint, tests) plus REUSE and citation checks; `docs/development.md`.
  Every experiment script records provenance in `results/provenance/<study>/<script>.json`
  (`provenance.track`), checked by a test.
- Experiments (phase 3): every top-level script moved to `experiments/<study>/` (rq1_benchmark,
  rq2_validity, rq3_channels, rq4_adaptation, raters, nap_scoring, injection, label_free, yasa_sweeps,
  usability); the SUMO fine-tuning and injection-training code moved there from `detectors/sumo/`.
  Protocol definitions and cache readers moved into the package (`protocols.benchmark`, version
  `benchmark.v1`; `data.cache`); the cache export and downloaders are `spindlebench cache` and
  `spindlebench download`. All paths come from `spindlebench.paths`; scripts and adapters run from any
  working directory. All 24 analyses re-run: every result identical to the snapshot.
- Cache manifests store signal paths relative to the manifest with forward slashes (portable); readers
  accept the old form too. Re-exported labels and DREAMS signals are identical.
- `spindlebench cache` now keeps BOAS in a full export (it was dropped unless `--boas-only` ran after).
- PhysioNet downloads fetch files from the AWS open-data mirror (checksums still from physionet.org).
- Provenance records replace local paths with `<root>` and `~`. SUMO runtimes moved from
  `detectors/sumo/runtime.csv` to `results/provenance/detections/sumo_runtime.csv`.
- Generated tables: `scripts/make_tables.py` -> `results/results_tables.md`.
- Retired: `run_yasa.py`, `test_dreams.py`, `check.py`, `main.py` (exploration only). DREAMS
  distribution files (`readme.txt`, `global_assessmentMethod.m`, licence) are no longer tracked.
- Licences found: `detectors/a7/a7.py` and `detectors/kcomplex_rules/spinky.py` are ports of GPL-3.0
  code and are GPL-3.0; `dreams_auto` detections are part of the DREAMS database (CC BY-NC-ND 3.0) and
  must not be published; SSSM weights have no licence (not redistributed).
- `affiliation` (Huet et al. 2022) is now a locked dependency pinned to commit 8d84498 instead of a
  manual clone in `third_party/`.

### Results
- `results/validity/greedy_vs_optimal*.csv` regenerated. The stored tables predated the A7 detector
  change of 2026-10-27 (`4337636`) and lacked four later detector configurations. Conclusion unchanged:
  greedy and maximum matching differ in 3 comparisons, by one true positive each, at ±1.0 s.
- `matching_greedy_vs_optimal.py` skips label-free recordings (BOAS), which made it fail.
